# Focused cleanup and safety review

The local provider code now owns metadata discovery, loopback validation and one shared model-selection guard. Settings re-exports its existing discovery API and the CLI uses the same guard. This removes duplicated local-runtime policy and unused settings imports without changing source research, prompts, quotation validation or AWS accounting.

The old CLI demo default could select the 30.8 GiB model that previously exhausted this 36 GiB Mac. CLI inference now defaults to the already-installed `gemma3:4b`, checks both generator and reviewer before creating either adapter, and rejects known model sizes above 35% of physical RAM (8 GiB fallback if RAM is unknown). Acknowledgment cannot override this block. Missing, nonnumeric, negative, zero, Boolean and non-finite sizes are treated as unknown and require explicit acknowledgment. Discovery uses metadata GETs only; it never loads or downloads a model. A missing model is an error, with no automatic alternative.

Both UI and CLI use the same macOS pre-inference memory-pressure check. Less than 25% reported free memory, unavailable probes and unrecognized probe output block inference. CLI requests use strict context bounds, a 2,048-token output cap and Ollama `keep_alive=0`; the 32,768-token request budget matches Settings and can be lowered explicitly. Ollama receives the context setting; other OpenAI-compatible servers retain their own server-side context settings. These are conservative guardrails, not a guarantee of peak memory use: disk size understates runtime memory and a generic server may not expose model size or configured context.

Invalid allowance text now returns a controlled validation error before AWS metadata checks. Existing exact account consent, grant expiry, shared per-session allowance, persistent $10 ledger, reservation-before-call and cached-query reuse behavior are preserved. Root's web changes separately serialize settings save/disable, allowing revocation while a research run is active.

Validation uses synthetic model metadata and stubbed AWS receipts, with socket connections blocked. The focused suite passed 92 tests covering CLI, providers/settings, vector queries, quotations/output and budget accounting. No actual metadata endpoint, inference endpoint, AWS call, download, stress test or comparative evaluation was run for this cleanup. The 23 saved evaluation judgments and frozen references remain unchanged.

Two small follow-ups remain explicit. Settings still imports atomic JSON saving and the conservative Converse reservation helper from the historical trial controller; moving those unchanged helpers to a neutral module should wait until the independent prompt experiment releases that file, then preserve compatibility aliases. A profile with InvokeModel permission but without ListFoundationModels currently fails the account/catalog check; supporting that restricted IAM setup would need an explicit catalog-unverified state, rather than silently asserting model availability.

The final independent review also found and fixed a consent transition: local-response approval now creates only a Titan query grant, and Bedrock generation requires an exact approved model binding. Missing/legacy bindings cannot silently authorize generation; disabling a query-only grant works without a model grant file. Five socket-blocked regression tests cover these transitions. The launcher identity now includes the cached Bedrock model/price catalog, so changed catalog settings cannot reuse a stale server. The final full offline check passed 247 application and 47 corpus tests.
